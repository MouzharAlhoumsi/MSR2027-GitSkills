
# Understanding the Structure and Reuse of AI Agent Skills in Open-Source Software Projects

This repository contains the code and supporting materials for an empirical study of AI agent skills in open-source software repositories. The study was prepared for the MSR 2027 Mining Challenge.

The analysis examines the structural characteristics of agent skill files and measures the extent to which identical skill contents occur across different repositories. It uses the GitSkills sample dataset and combines descriptive statistics, content-hash analysis, and sensitivity checks.

## Research Questions

The study addresses two research questions:

- **RQ1:** What are the structural characteristics of AI agent skills in open-source software repositories?
- **RQ2:** To what extent are identical AI agent skills reused across different repositories?

For RQ1, the analysis examines instruction body length, YAML frontmatter validity, and the presence of supporting files such as scripts and references.

For RQ2, skill contents are identified using Git blob SHA-1 hashes. A content hash is classified as shared when it appears in at least two distinct repositories. This measures exact-content overlap, not semantic similarity or the direction of reuse.

## Dataset

The study uses the publicly available GitSkills sample SQLite database.

- Sample repository: https://github.com/giuseppedestefanis/gitskills-sample
- Full dataset: https://huggingface.co/datasets/mvaccargiu/gitskills
- Dataset preprint: https://arxiv.org/abs/2608.10906

The sample contains:

| Property | Count |
|---|---:|
| Artifact occurrences | 29,786 |
| Distinct content hashes | 13,000 |
| Repositories | 11,841 |

The sample was constructed by selecting the 13,000 lowest Git blob hashes from the full dataset and retaining their recorded occurrences. Consequently, the sample is not a random sample of repositories, and its results should not be interpreted as population-wide prevalence estimates.

The dataset represents a July 2026 snapshot.

## Main Results

### Structural Characteristics (RQ1)

Across 13,000 distinct primary skill contents:

- Median instruction body length: 4,493 characters
- Mean instruction body length: approximately 6,816 characters
- Valid YAML frontmatter: 86.85%
- Supporting files present: 34.33%
- References present: 23.53%
- Scripts present: 10.21%

Supporting-file measurements describe the representative occurrence associated with each distinct content hash. They do not establish that every occurrence of the same content has the same surrounding files.

### Cross-Repository Reuse (RQ2)

The exact-content analysis identified:

- 2,854 distinct content hashes occurring in at least two repositories
- 21.95% of distinct content hashes classified as shared
- 18,855 artifact occurrences associated with shared content
- 63.30% of artifact occurrences associated with shared content

These measures use different denominators. The first percentage describes distinct contents, whereas the second describes artifact occurrences.

### Sensitivity Analysis

The analysis also considers the influence of large repositories, missing fork metadata, and filename restrictions.

Excluding the largest 1% of repositories by artifact count reduces occurrence-level overlap from 63.30% to 45.26%. Restricting the dataset to files named `SKILL.md` produces an overlap estimate of 63.41%.

These results illustrate how repository composition and filtering choices influence the reported overlap.

## Validation and Tests

The sample was checked for missing repository identifiers, missing content hashes, primary-representative uniqueness, and content-hash consistency.

The validation confirmed:

- 13,000 primary representatives for 13,000 distinct content hashes
- One primary representative per content hash
- Zero mismatches among the 13,000 independently recomputed primary Git blob hashes

Run the automated unit tests from the project root:

```powershell
python -m pytest tests/ -v
```

The tests cover cross-repository overlap, repeated contents within a repository, invalid inputs, numeric summaries, and percentage calculations.

## Interpretation and Limitations

The study measures exact-content overlap in a deterministically selected dataset sample. Several limitations are important:

- Identical hashes establish identical file contents, but do not identify copying direction, authorship, or the mechanism by which a skill was reused.
- Content hashes do not capture modified or semantically equivalent skills.
- The sample selection procedure may influence the observed distributions.
- Structural metadata for supporting files describes selected representative occurrences.
- Large repositories account for a substantial share of the observed artifacts.
- Missing fork metadata limits conclusions about repository independence.

These limitations should be considered when interpreting the descriptive results.
